# Issue #2 - 侧边栏显示功能开发计划

## 需求分析

### 原始需求
为mermaid图表增加一个侧边栏显示功能，使我可以一边看图，一边滚动会话内容。

### 用户场景
- 用户在ChatGPT或其他网站上查看包含mermaid图表的对话
- 当前：图表固定在原位置，查看时需要上下滚动
- 期望：可以将图表提取到侧边栏中独立显示，同时滚动阅读其他内容

### 目标
1. 实现侧边栏容器UI，支持图表在侧边栏中独立显示
2. 提供切换按钮，将图表从原位置移动到侧边栏或恢复
3. 侧边栏可折叠，不影响正常的页面浏览体验
4. 支持多个图表的管理和切换

## 技术方案

### 核心设计
- **方案**: 在页面右侧添加可折叠的侧边栏（约400px宽度）
- **交互**: 点击"移动到侧边栏"按钮，图表内容复制到侧边栏显示
- **回退**: 侧边栏有关闭按钮，可将图表恢复到原位置
- **适配**: 使用CSS媒体查询适配不同页面布局

### 实现架构
1. **UI组件**: 侧边栏容器、切换按钮、关闭按钮
2. **状态管理**: 跟踪哪些图表已移动到侧边栏
3. **内容迁移**: 将SVG图表DOM节点移动到侧边栏
4. **样式适配**: 确保图表在侧边栏中正确显示

## 技术要点

### 关键API
- `MutationObserver`: 监听动态添加的mermaid图表
- `mermaid.render()`: 重新渲染图表
- `CSSStyleSheet`: 注入侧边栏样式
- `postMessage`: 与扩展其他组件通信（可选）

### 性能考虑
- 图表仅在需要时复制到侧边栏
- 避免重复渲染相同的图表
- 使用`requestAnimationFrame`优化动画

### 边界情况处理
1. 页面窄于500px时隐藏侧边栏按钮
2. 页面已有固定侧边栏时的冲突处理
3. 多个扩展同时注入内容的场景
4. 图表渲染失败时的错误处理

## 风险评估

### 高风险
- 不同网站的CSS样式冲突可能导致侧边栏显示异常
- 复杂mermaid图表在移动过程中可能出现渲染问题

- 多个图表同时在侧边栏时的状态管理
- 页面滚动性能影响

### 缓解措施
- 使用Shadow DOM隔离样式（如果Chrome支持）
- 添加详细的错误日志
